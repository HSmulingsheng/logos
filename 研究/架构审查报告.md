## 1. 总览

**一句话**：数据层（FSRS、分片加载、语音 DSP）是扎实的，**展示层在最近几轮增量里分叉了**——同一件事普遍有 2–3 份实现，而原本设计好的公共件（`masteryOf`、`isCorrect`、`lettersOnly`、`allLogs`）反而成了死代码；架构健康度 **6.5/10**，属于「能跑、但每加一个功能就会再复制一份」的状态。

**最该动的三件事**：
1. **收敛展示层三套复制**（词条详情面板、逐词可点文本、选择题渲染）——这是所有重复的根，也是后续每次改动都要改三遍的原因。
2. **删死代码 + 修两个必修 bug**：`Reader` 查不到词时**完全没有反馈**（那段 UI 是不可达代码），`App.tsx` 的 `useEffect` 有两条 `return`（第二条永不执行，且预热的定时器无法取消）。
3. **抽 `applyProsody` 为纯函数供 app 与 tools 共用**，并按职责把 `tts.ts` 拆成 4 个文件——目前 `lib/tts.ts` 同时是引擎、DSP 胶水、缓存、播放器、错误兜底，任何一处改动都会波及全部。

| 维度 | 评分 | 说明 |
|---|---|---|
| 重复实现 | 4/10 | 展示层 3×，归一化 5×，发音按钮 3×，判题 2× |
| 死代码 | 5/10 | 27 个零引用导出、9 个未使用 import、5 个无效设置项 |
| 模块边界 | 6/10 | `psola.ts` 干净；`tts.ts`/`prosody.ts`/`Study.tsx` 过载 |
| 类型与数据流 | 6/10 | 类型基本贴合数据；`Settings` 用 `string` 导致 8 处 `as` 断言 |
| 性能 | 5/10 | 阅读器一次挂 3 万节点；`Browse` 过滤 O(卡片×15686) |
| 一致性 | 6/10 | 错误处理 3 种风格；「查不到词」3 种表现 |

**A4 · 高**｜`app/src/lib/tts.ts:202-235` vs `逻各斯/tools/gen_word_audio_prosody.ts:101-124`

**问题**：**`applyProsody` 是逐行复制**（同样的 `pcm→float32`、同样的中位数基频、同样的 `planAccent`/`pitchMarks`/`tdPsola` 调用、同样的 clamp 回 int16、同样的「失败原样返回」）。

| 差异点 | `tts.ts` | `tools` |
|---|---|---|
| 幅度参数 | 用 `prosodyAmp`（可调 0–2） | 硬编码 `1` |

| 失败处理 | `console.warn` | 静默 |

值得肯定的是：`tools` **已经** `import { planAccent } from '../app/src/lib/prosody'`、`import { tdPsola } from '../app/src/lib/psola'`（:33-34），所以 DSP 主体是共享的，**只有中间的胶水重复**。

**建议**：新建 `app/src/lib/prosodyPipeline.ts`（纯函数、零 DOM、零模块状态）：

```ts
export function shapeProsody(
  pcm: Int16Array, sr: number, events: EspeakEvent[], text: string, amp = 1,
): Int16Array
```

- `tts.ts:271-273` 改为 `shapeProsody(merged, samplerate, events, speak, prosodyAmp)`
- `tools/gen_word_audio_prosody.ts:149` 改为 `shapeProsody(pcm, SR, events, speak, 1)`

**前置约束**：`tts.ts` 顶层 `import` 了 `neuralTts.ts`（会 `caches.open`、`document.baseURI`）与 `flags.ts`，所以**不能**直接把 `applyProsody` 从 `tts.ts` 导出给 Node 脚本用——必须落到新文件。这也正是 A4 与 C1 应该一起做的原因。

### 2.6 一致性与错误处理（F）

**F1 · 中**｜`app/src/lib/data.ts:10,44`、`app/src/lib/wordLookup.ts:21`、`app/src/lib/aiTranslate.ts:84-86`、`app/src/lib/tts.ts:112-116`、`app/src/store/useStore.ts:205`、`app/src/pages/Study.tsx:121-139`

**问题**：**错误处理有 4 种互不兼容的风格**：

| 风格 | 位置 | 后果 |
|---|---|---|
| 抛异常 | `data.ts:10` `getJson` | `App` 显示错误页（:62-75）✅ |
| 静默返回空 | `data.ts:44` `.catch(() => ({}))`、`wordLookup.ts:21` `catch { /* 忽略 */ }` | 有注释说明是**刻意**的 ✅ |
| 抛自定义错误 + hint | `aiTranslate.ts:84` `AiError` | 调用方必须手动拼 message+hint（`ClassicalReading.tsx:164-167`、`Settings.tsx:347-350` 各拼一遍） |
| `console.warn` + 回退 | `tts.ts:113,232,286`、`neuralTts.ts:180,311` | 用户无感 ✅（刻意） |

**真正的问题在写入路径**：`useStore.submit`（:139-206）会 `await db.putCard/addLog/putDay`（:205），**没有 try**；`Study.record`（:121-127）`await submit(...)` 也没有 try，`gradeAndNext`（:136-139）`await record(); next()` 同样没有。
→ IndexedDB 写失败（配额满、隐私模式）时：**Promise 拒绝无人接 → 用户卡在这一题**，界面既不前进也不提示。`Study.answerChoice`（:142-151）里 `await record(...)` 失败后，`answered` 已置位（:145）但「继续」按钮的逻辑依赖 `answered`，看起来能用——实际 `next()` 仍会执行，所以数据静默丢失。这是最坏的一类：**看起来正常，进度没存**。

## 3. 建议的重构顺序

原则：**先删不改变行为的东西 → 再合并可见层的重复 → 最后才动有行为风险的计数与性能**。每一步都应能单独构建、单独验收。

## 4. 不建议动（看起来不优雅，但其实是对的）

写在这里是为了防止下一轮「顺手优化」把踩过的坑再踩一遍。这些地方的注释里已经记录了实测数据，**请保留注释本身**（它们比代码更值钱）。

1. **`lib/psola.ts` 整体**。三个函数、零依赖、零状态，且注释里写清了三条反直觉的约束（不许降采样 :44-47、输出位置按分析周期累加 :305、只在有声段做 :285）。`:48-49` 的 `const y = x` 与 `:97` 的内层 `rAt` 是残留，可以删，但**不要**「顺手」把自相关挪到降采样信号上——注释里记着恒等重建会从 1.0000 掉到 0.11。

2. **`lib/prosody.ts` 的 F0 参数**（`ACUTE_A = 0.45`、`CIRC_A = 0.45`、`FALL = 0.14`、`SMOOTH_WIN = 0.022`、`MORA_GAIN = 1.55`）。注释写明「用耳朵定」「HNR 损失与清晰度的折中」。这些不是可以「调整齐」的魔数。

3. **`tts.ts` 的「以整句为单位合成与缓存」**（:121-133、:243）。注释记录了踩坑：预生成与点击若用不同粒度，WASM 单线程会白跑一遍，3.6 秒被拖成 6.1 秒。`SentenceReader` 的「按句切分」是**播放粒度**，与合成粒度是两个概念，不要合并。

4. **`tts.ts` 的悬停预生成**（`prepareSpeech`，`SpeakSentence.tsx:47`、`SentencePlayer.tsx:126`）。看起来像「过度优化」，实际是神经推理 1–3 秒的必要掩盖。

5. **双语音引擎并存**（eSpeak + MMS 神经）。两套 `cache`、两套 `status`、两套失败回退看着重复，但一个是 24MB 共振峰、一个是 128MB VITS，缓存策略（blob vs CacheStorage）、语速实现（rate vs playbackRate）本质不同。**只应统一出口（C1），不应统一实现**。

6. **`data.ts` 的分片与按需加载**（`lesson-NN.ex.json` 拆分 :30-48）。注释有量化依据（474KB → 134KB，例句占 70%）。不要改回「整课一个 JSON」。

7. **`useStore` 用 `Map` 而非普通对象**。`cards` 作为 `Map` 是为了 O(1) 查 + 整体替换触发渲染；改成对象会让 `Home`/`Stats`/`Browse` 的遍历写法全部退化。

8. **`session.ts` 的「连对 4 次 + 动态插入 + 插在拼写区之前」编排**（:41-95）。这是产品核心机制（照搬「不背单词」），`planRequeue` 的 `spellAt` 定位逻辑不直观但正确——`buildQueue` 只铺「首次 + 拼写」两段、中间留给动态插入，是有意设计。**D3 只改计数，不要改编排**。

9. **`Sheet` / `Welcome` 的 `createPortal(document.body)`**（`ui.tsx:158-160`、`Welcome.tsx:47-49`）。注释说明：外层 `animate-fade-up` 的 `both` 填充会让 `transform` 永久保留，成为 `position: fixed` 的包含块。这是 CSS 事实，不是过度设计。

10. **`Study.tsx:52-57` 的 `dbg()` 与 `window.__autoDebug`**。看起来像调试残留，实际是 `scripts/smoke.mjs:25`、`scripts/offline-test.mjs`、`desktop/selftest.cjs` 依赖的自动化钩子。下沉 hook 时**必须保留**。（对照：`WordDetail.tsx:277` 的 `data-autoplay` 才是真的没人用，可删。）

11. **`getJson` 抛异常 + `loadLessonExtras` 静默** 的差异处理。前者是主数据（失败应整页报错），后者是锦上添花（缺例句不该阻塞学习），注释也写明了。**不要统一成一种**。

12. **`makeChoices` 的 `mulberry32(target.i)` 种子**（`session.ts:226`）。用词条 id 做种子，保证「同一题每次选项顺序一致」，避免用户重进后发现自己记的是位置。这看着像「假随机」，是有意的。

13. **`neuralTts.ts` 的分片下载与拼接**（:155-171）。托管平台单文件上限（Cloudflare 25MiB / GitHub 100MB）决定 114MB 必须切片，不是设计冗余。

14. **`grammar/exercises.ts` 的 `buildLevel` 重试与剔除**（:529-548）。某个题型在当前单元数据不足时会连续返回 `null`，`fails >= 12` 就剔除该题型——注释说明了「否则关卡的题会被静默截断成两三题」。这个 `guard < n*60` 的上限是必要的。

## 5. 待确认（没有运行期验证，不下结论）

1. **E7 的单选题窗口**：需要在一个**未预载**的课程上进入 `choice` 步骤才能复现（`App.init` 预载了 `activeLessons`，常规路径覆盖）。建议用 `mode:'new'` + 切换词书后立即开始来试。
2. **C4 的双路音频叠加**：`speakText` 与 `playAudio` 的 `current` 互不感知是代码事实；但浏览器是否真的同时出声、音量是否明显，需在 iOS Safari / Chrome 各试一次（iOS 对多个 `HTMLAudioElement` 有额外限制）。
3. **B4 的历史用户**：如果有用户已经把 `quizChoice` 关掉并存进 IndexedDB，直接删字段会让开关「消失」。因为 `loadSettings` 是合并语义，功能上无影响，但要不要给一次提示，属产品决策。
4. **F1 的写入失败**：IndexedDB 配额耗尽在桌面 Chrome 上很难触发，建议用 DevTools 手动 quota 限制或隐私模式验证一次，确认是「卡住」还是「静默丢数据」。
5. **`tools/*.py` 侧的归一化规则**：`Browse.tsx:13` 的注释说「与数据侧 `fold_key` 保持一致」，但 Python 侧的 `fold_key` 我没读（本次只审前端）。合并 `foldGreek` 前，**应先确认 `tools/build_app_data.py` 里 `fold_key` 的确切步骤**（尤其是是否做 NFC、是否处理 `ς`），否则 A8 会让搜索反而失配。
6. **`data/reading` 的段落粒度**：E1 若想按「小节」分页，需要数据侧提供小节号（当前 `Para` 只有 `g/e/zh`）。能不能从 Perseus 的原始结构里补出来，属数据侧问题。
