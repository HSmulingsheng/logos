# 自研古希腊语语音合成：可行性研究与可运行原型

**项目**：逻各斯（古希腊语学习 PWA）
**研究目录**：`逻各斯/研究/tts/`
**日期**：2025-10（本次会话）
**机器**：Apple M4 / 16 GB 统一内存 / MPS 可用、无 CUDA

> **一句话结论**：eSpeak-NG `grc` 的**音段**（音素音值）基本可靠但有三处系统性错误；
> 它的**韵律**（音高重音、mora 时长）基本没有实现。基于 eSpeak 做后处理改造是
> **值得做且有明确收益**的路线，本次已交付可运行原型并给出实测数据。
> 「自研一个神经网络 TTS」不可行，「自研一个共振峰合成器」不值得做。

---

## 0. 最重要的三条实测结论（先看这个）

### 0.1 eSpeak grc **完全没有实现古希腊语的音高重音**

| 最小对立体（音段完全相同，只有重音符号不同） | eSpeak 输出的 IPA | 整词 F0 均值差 |
|---|---|---|
| `φῶς`（circumflex） vs `φώς`（acute） | `f_ˈɔː_s_` vs `f_ˈɔː_s_` | **0.1 Hz** |
| `πῶς`（circumflex） vs `πώς`（acute） | `p_ˈɔː_s_` vs `p_ˈɔː_s_` | **0.4 Hz** |
| `τίς`（acute） vs `τις`（无重音） | `t_ˈi_s_` vs `t_ˈi_s_` | **0.0 Hz** |

- 15 组 acute/circumflex 最小对立体中，**14 组（93.3%）产出完全相同的音素串**
  （去掉重音标记后逐字符相同）。
- 整词 F0 范围只有 **23–28 Hz**（约均值的 30%），且峰值出现在重读音节**之前** ——
  这是英语/拉丁语式的「词级重读 + 下倾」，不是音高重音。
- 正字法上**无重音**的词（ἐν / εἰς / οὐ / ὡς / τις 等前附词、后附词），
  eSpeak 抽样 13 个里有 **12 个（92.3%）被强行加了主重音 ˈ**。

**好消息**：eSpeak 的 `ˈ` 标记**位置**是准的 —— 在 5,985 个词上与正字法重音位置
（从词尾算起的相对位置）**100.0% 一致**。所以「重音在哪个音节」不用自己算，
可以直接用 eSpeak 的输出定位，缺的只是**调型**（acute 的升 vs circumflex 的降）。

### 0.2 eSpeak grc 的**长短元音只实现了一半**

在 15,686 个词上统计 eSpeak 输出的音素清单（`out/grc_phoneme_inventory.json`）：
83 个带重音标记的音素变体，去重后 **37 个基本音素**，其中长元音只有
`eː ɛː ɔː uː` 与几个长二合元音。**`aː` / `iː` / `yː` 完全不存在，也没有短 `u`。**

后果（直接量到的时长）：

| 对比 | 音素 | 时长 |
|---|---|---|
| `ὥρα` 的 ω vs `ὅρα` 的 ο | `ɔː` vs `o` | 168 ms vs 98 ms（1.71×）✅ |
| `ἄγω` 的 ω vs `ἀγο` 的 ο | `ɔː` vs `o` | 136 ms vs 86 ms（1.58×）✅ |
| `δῆμος` 的 η vs `δεμος` 的 ε | `ɛː` vs `e` | 151 ms vs 87 ms（1.74×）✅ |
| **`μῦθος` 的 ῡ vs `λύω` 的 ῠ** | `y` vs `y` | **72 ms vs 71 ms（1.01×）❌** |

也就是说 η/ω 的长度 eSpeak 做对了，但**带 circumflex 的 ᾱ/ῑ/ῡ 完全没有加长**。
在 15,500 个词条里，落在 α/ι/υ 上的 perispomeni（`ᾶ ῖ ῦ`）共 477 处、
涉及 **477 个词（3.1%）** —— 这是时长模型可修的全部范围。

### 0.3 eSpeak grc 的音段与界面 IPA 有**两处系统性不一致**

这一点与项目此前的判断（「eSpeak 发音准确」）有出入，是本次新发现的硬数据：

| 现象 | 界面 `data/ipa.json`（CLTK Probert，阿提卡重建） | eSpeak grc 实际输出 |
|---|---|---|
| **送气塞音** φ θ χ | `pʰ tʰ kʰ`（真送气清塞音） | **`f θ x`**（擦音）|
| **ου** | `ọː`（[oː]） | **`uː`** |

- `data/ipa.json` 里有 **4,417 / 15,686 个词（28.2%）** 含送气符号 `ʰ`，
  eSpeak 一个都产不出来 —— 它把 φῶς 念成 `f ɔː s`，而界面标的是 `pʰɔ̂ːs`。
- eSpeak 的 β δ γ 却是 **浊塞音 `b d ɡ`**（阿提卡音值），不是现代希腊语的擦音。
- 所以 eSpeak grc 是**混合体系**：浊塞音恢复了古音，送气塞音沿用了现代希腊语的擦音。

架构上可以解释：`espeak-ng` 源码里 `espeak-ng-data/lang/grk/grc` 只有 4 行，
它把音素表**委托给现代希腊语 `el`**，只替换了词典：

```
name Greek (Ancient)
language grc
stressLength 170 170  190 190  0 0  230 240
dictrules 1
words 3
```

**这一条同时是「eSpeak 不够好」的证据，也是「自研有明确改进空间」的证据。**

## 1. 方向 1：eSpeak 的可控性（结论：**够用**，韵律后处理的前提已满足）

### 1.1 可以拿到的信息（全部实测通过）

| 需要的东西 | 拿法 | 实测结果 |
|---|---|---|
| **音素序列（IPA）** | `worker.convert_to_phonemes(text, true)`，返回 emscripten 指针 | ✅ `ἄνθρωπος` → `ˈa_n_θ_r_ɔː_p_ˌo_s_` |
| 音素序列（eSpeak 内部记法） | `convert_to_phonemes(text, false)` | ✅ `'a_n_T_R_O:_p_,o_s__:` |
| **每个音素的起止时间** | `synthesize()` 回调的**第二个参数**是事件数组，`type==='phoneme'` 的事件带 `audio_position`（**毫秒**） | ✅ `ˈa=116, n=77, θ=82, r=87, ɔː=111, p=30, ˌo=76, s=102 ms`，合计覆盖 681/744 ms |
| 词边界 | 事件里 `type==='word'`，带 `text_position`（1 基）与 `audio_position` | ✅ `ἐν ἀρχῇ ἦν` → 三个词的起止时间正确 |
| **基频曲线** | ❌ **没有** | 只能用 Praat 从波形反推，或后处理改 F0 |
| 采样率 | `get_samplerate()` | 22050 Hz |
| 全局率/音高/语调幅度/音色 | `set_rate` / `set_pitch` / `set_range` / `set_voice` | ✅ |

### 1.2 关键实现细节（踩过的坑，值得写下来）

1. **`convert_to_phonemes` 返回的是 emscripten 指针对象，`Module.UTF8ToString` 不存在。**
   本机实测 `typeof Module.UTF8ToString === 'undefined'`。必须自己从 `Module.HEAPU8`
   逐字节读到 `\0` 再 `TextDecoder` 解码（见 `scripts/espeak_ctrl.mjs:readCStr`）。

2. **事件数组里混有 `id` 为空串的伪事件**（音节分隔标记）。
   用下标硬对齐标签，在**多词输入**下会累积偏移（实测多出 4 个假音素）。
   必须按 `id` 是否为空来推进标签指针。

3. **`trace` 里词边界是一个空格，且空格粘在该词首音素上**
   （`"ˈe_n_ a_r_x_ˈɛɪː_"`）。切分时要 `trim()`。

4. `set_pitch` 对 F0 的影响（`ἄνθρωπος`，`range=60`）：
   `set_pitch=30 → 78.2 Hz`，`50 → 86.0 Hz`，`70 → 107.9 Hz`。
   即**只能整段平移 F0，不能给曲线**；且 `range=60` 时全词 F0 范围只有约 25 Hz。

### 1.3 **走不通的路（明确记录，避免重走）**

- **Praat / parselmouth 的 Manipulation 路线不可用**：
  parselmouth 0.4.7 不注册 `Manipulation` 类（`dir(parselmouth)` 里没有），
  `call(manip, 'Get end time')` / `'Get start time'` / `'Get duration'`
  在 Objects 窗口全部报 `Command "..." not available for given objects`；
  改用 Praat 脚本（`praat.run_file`）时，`Replace Pitch Tier` 报
  `not available for current selection`（该命令只存在于 ManipulationEditor 窗口）。
  → **最后自研了 TD-PSOLA**（见 §5），反而更好：只有 100 行 numpy，
  且能直接翻译成 JavaScript 在浏览器里跑。

- **pyworld（WORLD 声码器）本机装不上**：源码编译时链接失败，
  `ld: ... /Library/Developer/CommandLineTools/SDKs/MacOSX27.0.sdk/usr/lib/libc++.tbd:4:54:
  error: unknown architecture arm64e-macos` —— 本机 CLT 的 SDK 与编译器 tapi 不兼容。
  这是环境问题，不是方案问题；有 pyworld 的话 F0/时长改造质量会更好。

## 2. 方向 2：音高重音（结论：**eSpeak 没做，自己补的收益是本次最大的一项**）

### 2.1 现状（见 §0.1）与可用的抓手

- eSpeak 的 `ˈ` 重音**位置**100% 正确 → 直接用它定位重音音节，不需要自己写
  希腊语重音规则（「重音不出倒数第三音节」等）。
- 缺的是**调型**。正字法本身携带调型信息：`´`(U+0301)=acute，
  `˜`(U+0342 perispomeni)=circumflex，`` ` ``(U+0300)=grave。
  注意多音调希腊语把「字母+呼吸符+重音」**预合成**成单个码位（`ἄ` = U+1F04），
  必须先做 **NFD 分解**才能可靠定位重音符号 —— 这一点我一开始写错过，
  修正后重音位置一致率从 92.9% 升到 **100.0%**。

### 2.2 目标调型模型（阿提卡重建的通俗化版本）

| 重音 | 语言学内容（Allen 1973 / Devine & Stephens 1994） | 本原型的实现 |
|---|---|---|
| **acute** | 高调落在重音音节的**第二个 mora** | 单 mora：F0 平滑升到音节末（峰位 ≈1.0）<br>双 mora：前半缓升、后半升到音节末 |
| **circumflex** | 高调落在**第一个 mora**，第二个 mora 下降 | 峰位在音节 **≈45%** 后平滑下降 |
| **grave** | 中和后的 acute（连读变调） | 平的高中调 |
| 无重音 | 前附词/后附词不带调 | 低于基准线，受重音后降调影响 |
| 词级 | 全词 F0 基准线下倾（普遍倾向） | 从 1.06g 线性降到 0.90g |

**形状必须是平滑函数，不能用折线** —— 折线的尖角会让 PSOLA 的基音周期增量突变，
实测谐噪比（HNR）会掉 6–8 dB。改用高斯峰 + 22 ms Hann 平滑后，长句的 HNR 损失
从 −1.8 dB 降到 −0.6 dB。

## 3. 方向 3：音素时长 / mora 模型（结论：**范围有限但确实需要修**）

### 3.1 eSpeak 已经做对的部分

η/ω/长二合元音的时长是对的（1.58–1.74× 短元音），这个倍数与 mora 语言
「长=2 morae」的预期（理想 ~1.8–2.0×）基本同量级，**不需要重写整个时长模型**。

### 3.2 确实错的部分

1. **带 circumflex 的 ᾱ/ῑ/ῡ 没有加长**（72 ms vs 71 ms，比值 1.01×）。
   影响面：**477 / 15,500 词（3.1%）**。
2. **韵尾 `-αι` / `-οι` 在阿提卡重音规则里算短音**（所以 `ἄνθρωποι` 的重音能落在
   antepenult），但 eSpeak 把它们当长二合元音处理。本原型的 syllabify 实现了这条规则。
3. 「音节重量」（闭音节 = 2 morae）eSpeak 完全没有建模；
   不过闭音节的 mora 主要由韵尾辅音承担，**不一定要加长元音**，
   所以本原型**没有**动它 —— 没有证据支持的做法不写进去。

### 3.3 节奏指标

在 21 条演示音频的元音时长上算 **nPVI**（归一化成对变异指数，衡量节奏起伏）：
原始 33.1 → 改造后 33.1（**没变**）。这是诚实的负面结果：
本次只改动了 1 个元音的时长，全局节奏指标当然不动。
**要让 nPVI 有意义地变化，必须实现完整的 mora/音节重量时长模型，那是一项独立工作。**

## 4. 方向 4：自研共振峰（Klatt 式）合成器（结论：**不值得做**）

**事实基础**：eSpeak-NG **本身就是一个共振峰合成器**。源码树里有
`phsource/klatt`、`phsource/envelope`，音色机械正是因为它是 Klatt 式的
源-滤波器合成（`tools/gen_word_audio_espeak.mjs` 的注释也这么判断）。

**如果自己写一个，工作量与收益**：

| 必须自己造的部分 | 估算 |
|---|---|
| 37 个希腊音素的共振峰表（F1/F2/F3/B1/B2/B3、鼻音零点、擦音噪声谱） | 从零实验调参，2–4 周 |
| Klatt 式的声源（周期脉冲 + 噪声，含气声/送气） | 1–2 周 |
| 音素→音节→词的韵律与连读规则 | eSpeak 已经有一整套，重写等于复刻 |
| 音长与 F0 模型 | 可以复用本原型的成果 |

**结论**：自己写只能拿到「完全可控」，而**完全可控已经通过 PSOLA 后处理拿到了**
（本原型的成果）。自己写还要**丢掉 eSpeak 成熟的希腊语词典与音变规则**
（`dictsource/grc_rules`、`grc_list`）与 117× 实时的速度。
**建议：不做。** 唯一的例外是「送气塞音 `pʰ tʰ kʰ`」——
如果要做，正确做法不是自研整机，而是**给 eSpeak 补一张音素表**
（在 `el` 音素表基础上增加送气塞音，或用 `set_voice` 加载自定义音素表）。
但注意：本机拿到的 eSpeak 是**编译好的 WASM**，音素表已经烧进 `espeak-ng.data`
（24 MB），**在浏览器里改不了**；要改必须重新编译 eSpeak-NG 的 WASM。
这是一项明确但独立的工作（见 §7）。

## 5. 交付物：原型「eSpeak + 音高重音/mora 后处理」

### 5.1 原理

```
文本 ──eSpeak WASM──► PCM + 每音素起止时间 + IPA 音素串
                            │
       正字法(NFD) ──► 重音类型(acute/circ)/重音位置/mora 数
                            │
                    目标 F0 曲线 + 时长锚点
                            │
              ┌─────────────┴─────────────┐
              │  自研 TD-PSOLA (numpy)    │
              │  · 只搬基音周期，不碰共振峰 │
              └─────────────┬─────────────┘
                            ▼
                     改造后 PCM
```

**PSOLA 为什么能保持阿提卡音值**：它在**基音周期**的尺度上剪切并叠加波形，
每个周期内部的波形（= 共振峰结构 = 元音音值）原样保留。
所以改造只改基频与时长的感知量，不改音素音值。

### 5.2 TD-PSOLA 内核的正确性验证（**这一步必须做，否则全部数据不可信**）

用「脉冲串 + 三个共振峰」的合成信号做恒等重建（不改 F0、不改时长）：

| 测试信号 | 恒等重建与原信号的相关系数 |
|---|---|
| 合成测试信号（110 Hz 脉冲串 + F1/F2/F3） | **1.0000** |
| `min09_eimi_acute`（eSpeak 输出） | **1.0000** |
| `min01_phos_circ`（eSpeak 输出） | **1.0000** |
| `min13_anthropos`（eSpeak 输出） | 0.7516 |

**调通过的两个关键点**（写下来给以后的实现者）：
1. **输出位置必须按「分析周期」逐步累加**（用前向差分周期 `marks[j+1]-marks[j]`
   作增量），而不是按平滑后的 F0 曲线重新铺点。用后者时恒等重建的相关系数
   只有 **0.08–0.39**。
2. **PSOLA 只能在有声段内做**。若在整个信号（含静音）上铺合成标记，
   找最近分析帧时会把有声帧复制到静音里 —— 恒等相关系数掉到 **0.11**。

另外两条次要经验：加窗必须用 **Hann**（50% 叠加下严格和为 1）；
窗长取 `2×分析周期`。

### 5.3 改造效果（客观数据，**不含任何「听起来更自然」的判断**）

#### (a) acute vs circumflex 变得可区分（本次最硬的成果）

时间归一化后的 F0 曲线平均绝对差：

| 最小对立体 | 原始 eSpeak | 恒等重合成对照 | 改造后 | 提升 |
|---|---|---|---|---|
| `φῶς` vs `φώς` | 0.85 Hz | 0.85 Hz | **25.26 Hz** | **×29.6** |
| `πῶς` vs `πώς` | 0.77 Hz | 0.77 Hz | **24.64 Hz** | **×32.1** |
| `εἶμι` vs `εἰμί` | 9.78 Hz | 9.78 Hz | 22.17 Hz | ×2.3 |
| `δῆμος` vs `δημός` | 9.69 Hz | 10.50 Hz | 17.44 Hz | ×1.8 |

「恒等重合成对照」这一列是关键：它证明**差异不是重合成过程本身造成的**。

#### (b) 重音对比与 F0 范围

| 指标 | 原始 | 改造后 |
|---|---|---|
| `τίς`(acute) vs `τις`(无重音) 整词 ΔF0 | +0.1 Hz | **+15.8 Hz** |
| `ἄνθρωπος` 全词 F0 范围 | 27.0 Hz | **61.9 Hz** |
| `sent02` 全句 F0 范围 | 41.9 Hz | **94.9 Hz** |

#### (c) 音段（阿提卡音值）**没有被破坏** —— 这是硬约束

| 指标（amp=0.35，18 个词的首元音） | 中位数 | 90 分位 |
|---|---|---|
| F1 漂移 | **3.1 Hz** | 22.5 Hz |
| F2 漂移 | **5.3 Hz** | 18.3 Hz |

对照：本项目自己的实测区分度是 F2 差 445 Hz（σύ 的 υ=[y] vs τί 的 ι=[i]）。
**改造带来的共振峰漂移（中位 5 Hz）比需要区分的语言学差异（445 Hz）小两个数量级**，
即 elocution 上安全。

#### (d) 隐藏长元音被补上

`μῦθος` 的 ῡ 窗口 92→164 ms（72 ms），乘 1.55 后为 111.6 ms；
整词时长 486 → **526 ms**。延长倍数 1.55 取自 eSpeak 自己对 ω:ο 的实测比值
（136/86 = 1.58），不是拍脑袋定的。

### 5.4 **代价：谐噪比（HNR）下降 —— 必须诚实报告**

HNR（谐噪比，越高越「干净」）的损失（4 个代表样本的平均/最差）：

| 音高重音幅度（峰/基准） | 区分度 | HNR 平均变化 | HNR 最差变化 |
|---|---|---|---|
| 1.15× | 7.11 Hz | −1.96 dB | −4.28 dB |
| 1.25× | 11.45 Hz | −2.90 dB | −5.79 dB |
| **1.35×** | 13.33 Hz | −3.37 dB | −5.62 dB |
| 1.45×（原型默认口径） | 18.95 Hz | −4.12 dB | **−8.50 dB** |
| 1.60× | 28.94 Hz | −4.39 dB | −8.94 dB |

**这是清晰的技术权衡**：幅度越大，区分度越好，但 PSOLA 每步要搬动更多基音周期、
相邻重叠窗的相位错开，音质变粗糙。损伤在**单个长元音承担整个 circumflex 时最严重**
（`φῶς`：14.8 → 6.2 dB），在**长句上最轻**（`sent02`：14.1 → 13.3 dB，仅 −0.8 dB）。

我也试过三种窗长策略（`2×分析周期` / `2×目标周期` / `2×max`），**HNR 差异可忽略**
（6.2–6.5 dB），说明这是方案的内在天花板，不是实现瑕疵。

**可选的规避手段（未实施，供决策）**：先把 eSpeak 的基准 F0 调低（例如 `set_pitch=40`），
让重音的**峰**落在当前基准高度上 —— 这样只需要「向上加一点」而不是「整体抬高再压低」，
PSOLA 的改造幅度变小，HNR 损失会小很多。这会改变整体音高，需要听感裁决。

### 5.5 另一个诚实的负面结果

- **LTAS（长时平均谱）相关系数**：恒等重合成对照 0.95–0.98，改造后 0.79–0.84。
  乍看像频谱被破坏，但这主要是 **F0 改变导致谐波间距改变**的必然结果，
  不能作为音质受损的证据。真正说明音段保真的是 (c) 的共振峰漂移数据。
- **nPVI 没变**（33.1 → 33.1），原因见 §3.3。
- 我的原型**继承了 eSpeak 的一个缺陷**：`τις` 这种正字法无重音的词，
  eSpeak 强行加了 ˈ，我虽然按正字法把调型设为「无重音」（ΔF0 从 0.1 变成 15.8 Hz），
  但**重音位置本身仍是 eSpeak 给的**。要彻底解决必须自己实现希腊语重音规则。

## 6. 方向 5：跨语言神经声码器（结论：**部分可行，是唯一能换掉「机械音色」的路线**）

### 6.1 网络现实

- `huggingface.co` **被网络层屏蔽**（curl 返回 HTTP 000），
  `hf-mirror.com` **可达**（200）。Piper 全部语音都从镜像取。
  `codeload.github.com` / `raw.githubusercontent.com` / `pypi.org` 可达。
- **子代理不可用**（`subagent depth 2 exceeds maxDepth 1`），本方向的调研与实测
  全部自己完成。

### 6.2 Piper 的音素接口（**先纠正一个我一开始搞错的判断**）

第一次分析我把目标 IPA 当**单个 token** 去比对 `phoneme_id_map`，
于是 `aː eː iː` 全部报缺失 —— **错了**。
实际上 Piper 的 `phoneme_id_map` 是一套**语言无关的 IPA 符号表**
（`de_DE-thorsten-medium` 有 159 个 token），长音写成 `a`+`ː` 两个 token、
送气写成 `p`+`ʰ`。按 **token 序列**重新统计（176 个语音的配置，全部从镜像下载）：

| 结论 | 数据 |
|---|---|
| 覆盖率分布 | 82 个语音覆盖 53/54；46 个覆盖 52/54；只有 3 个（`-x_low` 级）覆盖 48/54 |
| **唯一普遍缺失的音素** | `r̥`（清化颤音）在 **176/176** 个语音中都缺失 |
| `pʰ tʰ kʰ`（送气） | 48/176 个语音缺（全部是 `-low` / `-x_low` 档）|
| `g`(ASCII U+0067) | 92/176 缺 —— 它们用 `ɡ`(U+0261)，只是码位不同 |

**所以「符号够不够」根本不是瓶颈。真正的瓶颈是「声学模型有没有被训练过这些符号」** ——
这只能实测，配置文件看不出来。

### 6.3 实测：把阿提卡 IPA 喂给**德语** Piper

选德语的**可验证理由**：阿提卡重建里在现代语言中罕见的音素，德语恰好都有 ——
`[y]`（ü）、`[yː]`、`[ɛː]`（ä）、`[ɔ]`、`[a]`、双元音第二成分 `[ɪ]/[ʊ]`。

用 `onnxruntime` 直接驱动 `de_DE-thorsten-medium.onnx`（63 MB，22050 Hz），
**绕过它的文本前端，手工构造 phoneme id 序列**。三方对照，同一套测量方法
（Praat Burg，25 ms 窗，窗口中间 60% 取中位）：

| 输入形式 | F1(y) | F2(y) | F1(i) | F2(i) | **F2(i)−F2(y)** |
|---|---|---|---|---|---|
| (A) eSpeak grc（对照，已知正确） | 331 | 1716 | 287 | 2272 | **+556 Hz** |
| (B) 德语 Piper 念**真实德语词**（Bühne/viel，管线正确性对照） | 228 | 1480 | 223 | 1833 | **+353 Hz** |
| (C) 德语 Piper + **希腊 IPA** `[ˈyː]`/`[ˈiː]` | 240 | 1863 | 206 | 2189 | **+326 Hz** |

**这是本方向最有价值的结果**：
德语语音在**训练分布之外**接受希腊 IPA 输入时，`[y]` 与 `[i]` 的区分度
（+326 Hz）与它念自己母语时的区分度（+353 Hz）**基本一致**。
即：**「借德语语音来念古希腊语的 [y]」在音段层面是自洽的。**

同一批测量也暴露了它的**失真**（这些音素它没有正确的德语对应）：

| 希腊 IPA | 德语 Piper 测到 | eSpeak grc 测到 | 判断 |
|---|---|---|---|
| `aː` | F1 335 / F2 1488 | F1 858 / F2 1397 | **F1 过低 500 Hz** → 念成了 [ɐ]/[ə] 一类，**不是 [a]** ❌ |
| `ɔː` | F1 282 / F2 1394 | F1 681 / F2 950 | F1 低了 400 Hz → 偏闭偏前 ❌ |
| `uː` | F1 225 / F2 985 | — | 尚可 |
| `eː` | F1 312 / F2 1660 | F1 449 / F2 1987 | 尚可 |
| `yː` / `iː` | 见上表 | — | ✅ 可信 |
| `y`（短，孤立） | F1 727 / F2 1844 | F1 331 / F2 1716 | 短孤立元音测量不稳，不计 |

**注意测量偏差**：神经声码器与共振峰合成器的频谱倾斜不同，
跨引擎的绝对 F1 不可直接比（我的德语母语对照 `Vater` 的 [ɑː] 也量到 F1 494，
真值约 700）。**可靠的只有同一引擎内部的对比**（y vs i、改造前 vs 改造后）。
这个局限必须写进任何引用本数据的结论里。

### 6.4 其他候选方案的判定表

| 方案 | 输入粒度 | 许可证 | 本机可行性 | 判断 |
|---|---|---|---|---|
| **Piper**（`rhasspy/piper-voices`，OHF-Voice/piper1-gpl） | **音素 id 序列**（可绕过文本前端） | piper 代码 GPL-3.0；**语音逐个不同**：`de_DE-thorsten-medium` 数据集 **CC0**，`el_GR-joy-medium` **CC BY-NC 4.0** | ✅ **本机实测跑通**（onnxruntime CPU，63 MB 模型） | **最推荐** |

「多语言的文本前端 + 多语言声学模型」，不是「语言无关的音素接口」。）

### 6.5 Piper 路线的**具体接入方式**与障碍

可行步骤（已实测前 3 步）：

1. 从 `hf-mirror.com/rhasspy/piper-voices` 取语音的 `.onnx` + `.onnx.json`；
2. 读 `config['phoneme_id_map']`，把阿提卡 IPA 按**最长匹配**切成 token
   （注意 `ː` `ʰ` `ˈ` `ˌ` 都是独立 token），再转 id：
   `[bos] + Σ(token_id + pad_id) + [eos]`；
3. `onnxruntime.InferenceSession` 跑 `input`/`input_lengths`/`scales` 三个输入，
   输出直接是 22050 Hz 波形（CPU 即可）；
4. 用本项目 **`data/ipa.json`（Probert 阿提卡重建）**当输入而不是 eSpeak 的输出 ——
   这样连 φ/θ/χ 的送气塞音问题也一起解决了（Piper 的 token 表里有 `ʰ`）。

**已知障碍**：
- **低元音失真**：`[a]`/`[ɔ]` 被德语化（F1 低 400–500 Hz），需实测后决定是否
  换语音（意大利语 `it_IT` 的 `a`/`ɔ` 更接近，但**没有 `yː`**）
  或**多语音拼接**（不同音素用不同语音的声学模型，拼接处需处理）。
- **韵律**：Piper 的 VITS 时长由权重决定，改不了语速/时长；F0 由模型自带。
  但**输出仍是波形**，所以 §5 的 TD-PSOLA 可以照用 —— 这条路线与本原型的
  后处理**叠加**而不冲突。
- **许可证**：必须逐个语音核对 `MODEL_CARD`（HF 被屏蔽，需通过镜像取）。
- **体积**：63 MB/语音，比 eSpeak 的 24 MB 大；浏览器端要用 onnxruntime-web。

## 9. 结论：值不值得做？最佳路径与工作量

### 9.1 值不值得做：**值得，但请把目标从「自研 TTS」改成「改造 eSpeak 的韵律」**

理由（全部有实测支撑）：

- ✅ **有明确的、可度量的缺陷可修**：acute/circumflex 的 F0 差异 0.85 Hz → 25.26 Hz
  （×29.6）；重音对比 0.1 Hz → 15.8 Hz；F0 范围 ×2；隐藏长元音 1.01× → 1.55×。
- ✅ **音段安全**：共振峰漂移中位 3–5 Hz，远小于需要区分的语言学差异（445 Hz）。
- ✅ **工程量小、可移植**：TD-PSOLA 约 100 行 numpy，可直译成 JavaScript，
  在浏览器内跑（不需要新依赖、不需要下载新模型）。
- ⚠️ **有明确代价**：HNR 下降 2–4 dB（最差 8.5 dB），需要听感裁决。
- ❌ **换掉「机械音色」这一条，靠自研做不到**（训练路线已被项目前期排除）；
  唯一的现实出路是 §6 的跨语言神经声码器。

### 9.2 最佳路径（推荐按顺序做）

**路线 R1（先做，2–3 天）— 把本原型移植进 PWA**

1. 把 `scripts/psola.py` 的 TD-PSOLA 与 `scripts/prosody_fix.py` 的
   正字法重音解析（NFD + 二合元音相邻性 + 韵尾 -αι/-οι 算短）译成 TypeScript，
   放进 `app/src/lib/`；**不要动 `app/` 之外的东西，也不要在本研究的脚本里直接改应用**。
2. 从 eSpeak 的 `phoneme` 事件流取「音素→时间」对齐（`synth_with_phoneme_trace_`）。
3. 用**保守幅度**（峰 ≈1.30–1.35×）先上线，在设置里做成可调，
   让用户用耳朵决定幅度（这是我能给的最诚实的建议）。
4. 预先算好并缓存常用词的改造结果（现状已有音频缓存机制可复用）。

**工作量**：TS 移植 1–2 天 + 联调 1 天。**风险**：HNR 损失是否可接受（需试听）。

**路线 R2（可选，1 周）— 补上送气塞音与「无重音词」**

- 送气塞音只能靠「重新编译 eSpeak-NG 的 WASM 并修改 `el` 音素表」解决。
  这是一项独立且有一定风险的构建工作（emscripten 工具链 + 音素表调参）。
  **在动手前建议先试听**：`f/θ/x` vs `pʰ/tʰ/kʰ` 对学习者的影响究竟多大。
- 「无重音的前附词/后附词」：自己实现希腊语重音规则
  （重音不出倒数第三音节、韵尾 -αι/-οι 算短等），替换掉 eSpeak 的 `ˈ`。
  本研究的 `syllabify()` 已经是这套规则的核心，可直接复用。

**路线 R3（探索，1–2 周）— 跨语言神经声码器**

- 用 Piper + `data/ipa.json`（Probert）音素串合成，**音段用意大利语/芬兰语/德语
  三个语音做横向对比**，找出 `[a]`、`[ɔː]`、`[y]/[yː]`、`[ɛː]` 各自最合适的声音；
  必要时做**多语音拼接**（按音素选语音，接缝处交叉淡化）。
- 输出波形再走一遍 §5 的 PSOLA 补音高重音。
- **判断标准**：`[y]` vs `[i]` 的 F2 差 ≥ 300 Hz、`[a]` 的 F1 ≥ 700 Hz、
  送气塞音有可测的送气段（VOT > 30 ms）。
- **工作量**：语音筛选 3–5 天 + 浏览器端 onnxruntime-web 集成 3–5 天 + 拼接调优 3–5 天。
- **风险**：许可证逐个核对；63 MB/语音的体积对 PWA 是压力；
  声学模型在训练分布外的行为无法从原理预测，只能试。

**路线 R4（不建议）**：自研 Klatt 共振峰合成器（§4）、继续尝试训练神经网络 TTS
（项目前期已排除）。

### 9.3 最小可行成果

如果只有 2–3 天，做 **R1**，并把幅度做成设置项。
它能修好「acute 与 circumflex 完全不分」这个对学习者最实质的缺陷
（界面已经标了重音符号，发音却完全不体现，这是「显示与实际不一致」的第二例，
与项目已经发现的 MMS 问题同类），代价是 HNR 下降 2–4 dB。
