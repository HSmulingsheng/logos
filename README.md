# 逻各斯

**一个完整的古希腊语学习平台**：分级词书 · 语法闯关 · 宗教/哲学/文学/历史四体裁阅读 · 听力 · 神经语音。
间隔重复用 FSRS-6，全部数据留在本机，可离线使用。

词表源自 Anki 牌组 `Ancient Greek Vocab`（**15,686 个词条**），
例句取自 SBLGNT（新约）与 GLAUx（古典）真实语料，古典阅读文本取自 Perseus Digital Library。

## 快速开始

需要 **Node.js 18+** 与 **pnpm**。

```bash
git clone <你的仓库地址> logos && cd logos
cd app
pnpm install

# 从 npm 依赖里同步两个运行时（eSpeak 语音引擎、ONNX Runtime）
node scripts/sync-espeak.mjs
node scripts/sync-neural.mjs     # 需要先准备神经语音模型，见下

pnpm dev                          # 开发模式
pnpm build                        # 构建到 app/dist
node scripts/serve.mjs 4178       # 起本地服务
node desktop/bundle.mjs           # 打包成 .app（macOS）
```

**三种用法**，数据完全共用：

| 形态 | 怎么用 | 说明 |
|---|---|---|
| **网页版** | `node scripts/serve.mjs 4178` | 本机 `http://127.0.0.1:4178/`；**手机/平板同 Wi-Fi 扫码即可用** |
| **PWA（可装到手机/桌面）** | 网页版里「我的 → 离线使用 → 缓存全部词表与发音」 | 装成 App 后**断网也能学** |
| **桌面 App** | `node desktop/bundle.mjs` → 双击 `app/release/逻各斯.app` | Electron 打包，自带运行时 |

首次打开桌面 App 若被 Gatekeeper 拦下，**右键 →「打开」**即可（本机自签，无开发者证书）。

## 已实现的功能

**词书**：保留牌组原有的 A2→C2 分级结构（01–31 课，原牌组缺第 22 课），共 30 本，可同时选多本，进度共享。

**学习循环**：新词每 5 个一批「先学后测」，复习与到期卡穿插其间。

**一组学完可选拼写**：每学完 5 个新词，会先弹出一次岔路口——
列出这一组的词，问要不要现在拼写一遍（`1` 拼写 / `2` 或 `Enter` 跳过）。
选拼写会把这一组的 5 道拼写题插入队列，做完再回到原本的测验流程。
可在「我的 → 设置 → 练习模式」里关掉这个询问。

**新词四选一**：新词一出现就**自动发音**，并给出 **1/2/3/4 四个释义选项**；
作答后立刻显示对错、完整词条（中英释义、词根词缀、真实语料例句、词形变化）——**此时会再念一次**，再按键继续。

**发音时机**：单词出现即自动朗读；**点击词形**（或复习卡点「显示答案」、拼写提交后）会再朗读一次；任何时刻按 **R** 重放。
词库页点开词条详情也会自动朗读。

**键盘操作**（全流程可不用鼠标）：

| 键 | 作用 |
|---|---|
| `1`–`4` | 选择选项 / 复习环节的四档自评（忘记/模糊/记得/熟练）/ 听力题选择 |
| `空格` | 复习卡显示答案 |
| `Enter` | 提交拼写 / 继续下一步 |
| `R` | **重放发音**（拼写输入框、「词条详情」「读新约」里也生效；希腊语用不到拉丁字母 r） |
| 点击词形 | 显示释义并朗读一次 |
| `Esc` | 退出本轮（进度已保存） |

**四种卡片 / 测试形式**

| 形式 | 说明 |
|---|---|
| 新词学习 | 大字词形 + 自动发音 + 1/2/3/4 四个释义选项 → 作答后展开完整词条 |
| 复习 | 词形回忆，四档自评（忘记 / 模糊 / 记得 / 熟练），**按钮上直接显示 FSRS 预测间隔** |
| 选义 | 给出希腊语词，四选一选中文释义（干扰项优先取同词性、长度相近的词） |
| 听音辨词 | 只播发音，从四个希腊语词形中选出正确拼写 |
| 拼写 | 给出释义 + 发音 + 首尾字母提示，输入希腊语单词；**忽略变音符号也算对**，但会提醒重音差异 |

**调度**：FSRS-6（`ts-fsrs` 5.4.2，MIT）。目标保持率、每日新词数、复习上限、学习步骤均可调；
支持「按课次」或「按新约词频」两种学习顺序。

**导航**：底部三个入口——**学习**、**词书**、**我的**。切换后再回来，仍停在上次的分栏。

**学习**页含四个板块：

| 板块 | 内容 |
|---|---|
| **单词** | 今日任务（新词/复习）、开始学习、数据速览、当前词书进度、读新约与专项复习入口 |
| **语法** | **闯关**（10 章 50 关的游戏化路径）+ **速查**（字母、词尾、变格范例）+ **教材对照**（Smyth） |
| **阅读** | 读新约（SBLGNT + 和合本对照，点词查义）、27 卷选读、**自动记住上次读到的章节**、读法建议 |
| **听力** | 听音辨词 / 听写两种模式，取材可选「当前词书」或「已学过的词」，每轮 20 题，只练听力、不进记忆曲线 |

### 出题机制：连对 4 次才算学会

新词与复习都按**「不背单词」的逻辑**出题（其依据是《学习这回事》里的「单人纸牌游戏法」）：

1. 一个词必须**连续答对 4 次**才算学会
2. 中间**错一次，「连对」清零**，从头重新累计
3. 每次重新出现的**间隔逐次拉长**（插入位 3 → 6 → 9 → 12）
4. 题型在**四选一选义**与**翻卡自评**之间交替
5. **全部词都辨识通过之后，才统一进入拼写**

第 2 轮之后的题目不是组卷时算好的，而是在作答时由 `planRequeue()`
动态插入队列——并且**始终插在拼写区之前**，这样第 5 条才成立。
逻辑自检见 `app/scripts/session-test.ts`（10 项断言，含该不变式）。

### 阅读板块：四个体裁统一

宗教（新约）、哲学、文学、历史**共用同一套阅读实现**，字号、逐词查义、
译文切换、视觉完全一致：

| | 实现 |
|---|---|
| 逐词可点 | `components/ClickableGreek.tsx` |
| 点词查义 | `lib/wordLookup.ts`（两处共用，不再各写一套） |
| 正文字号 | `text-[19px] leading-loose`（四个体裁一致） |
| 译文切换 | 中 / 英 / 隐藏 |
| 查不到时 | 显示词形 + 到 Logeion 的出口 |

**查词覆盖率有客观上限。** `data/formindex.json` 建自**新约词表**（15,686 词的
屈折形式），古典文本超出这个范围：哲学 74~77%、历史 60~72%、文学（荷马）
46~59%，总体约 65%。查不到时给 Logeion 链接，不会点了没反应。

### 古典文本的中文译文

**没有可自由分发的现成中译本**——荷马、柏拉图、修昔底德的中译（罗念生、
王焕生、王以铸等）全在版权期内，维基文库搜出来全是噪声（匹配到现代法律文书）。
所以走 LLM **从希腊语原文直译**。

**已完成：15 部作品 · 13,084 段 · 100%**（哲学 6 部、文学 5 部、历史 4 部）。

```
tools/make_reading_zh_batches.py   切批次（每批约 3.5 万字符）
   → 子代理并行翻译 → data/zh_reading/out/<同名文件>.json
tools/migrate_zh_keys.py           必要时把下标键迁移成哈希键
tools/merge_reading_zh.py          汇总 → merged.json，注入阅读数据
```

两个**踩过的坑**，都写在对应脚本的注释里：

1. **段落的键必须用内容哈希，不能用「作品#章#段」下标。**
   Perseus 里《尼各马可伦理学》有 9,341 字符的超长段，按句子切开后下标整体平移，
   已译内容就对不上了。哈希键只让**真正被改动的段**失配。
2. **批次文件名也必须用内容哈希。**
   曾用 `batch-000/001…` 编号，`--skip-done` 重建后编号平移，新批次**覆盖**了
   先前译好的同名文件，把已 100% 完成的《安提戈涅》《美狄亚》冲成 0%。

### 首屏加载：两道优化把 2.2 MB 压到 0.7 MB

实测（本地、未压缩；线上有 gzip 会更小）：

| | 优化前 | 优化后 |
|---|---|---|
| 字体 Regular | 949 KB | **104 KB** |
| `lesson-01.json` | 761 KB | **141 KB** |
| JS 包 | 436 KB | 436 KB |
| **首屏合计** | **约 2260 KB** | **约 738 KB（省 67%）** |

**① 字体子集化**（`tools/subset_fonts.py`）

Gentium Plus 是 SIL 为语言学研究设计的字体，收录上千字形，单个 TTF 就有 949 KB，
而本项目实际只用到约 270 个字符。子集化 + 转 **woff2** 后：

| 档位 | 原 TTF | woff2 |
|---|---|---|
| Regular | 949 KB | 104 KB |
| Bold | 954 KB | 111 KB |
| Italic | 1005 KB | 114 KB |
| **合计** | **2907 KB** | **329 KB（省 89%）** |

字符集**从真实数据采集**（IPA / 词表 / 新约 / 古典文本 / 界面文案），不凭猜。
源 TTF 放在 `tools/fonts-src/`（**不在 `public/`**，否则 Vite 会把 2.9 MB 原字体也打进部署包）。

```bash
tools/venvs/font/bin/python tools/subset_fonts.py            # 生成
tools/venvs/font/bin/python tools/subset_fonts.py --report   # 只报告
```

**⚠️ 改动数据后必须重新生成**，否则新增字符会变成豆腐块。
`app/scripts/font-test.mjs`（10 项）就是守这个的：它不看文件大小，而是
用 canvas 量渲染宽度、逐个字符查缺字、并检查组合变音能否叠加。

**② lesson 数据拆分**

实测整课 JSON 里 `ex`（例句）与 `fm`（词形变化）**占 70%**，
而它们**只在词条详情里用**——首页与学习卡正面都不需要。

所以生成时拆成两个文件：

```
lesson-01.json      141 KB   核心（词形/释义/音标/音频路径…）—— 首屏关键路径
lesson-01.ex.json   627 KB   例句与词形变化 —— 打开详情时才拉
```

`WordDetail` 用一个 `useWordExtras` 钩子按需取，**拉不到就安静地不显示**，
不影响任何主流程。SW 预缓存与离线缓存都加了伴随文件（前 6 课）。
`detail-test` 里专门加了断言守这个拆分——拆出后详情页必须仍能渲染例句。

### 单词发音与句子走同一条管线

**曾经不一致，是个真实的坑。** 单词音频是离线批量生成的，当时只有
「eSpeak 出 WAV → afconvert 转 m4a」，**没有**应用里后来加的韵律与音值修正，
于是同一个词的单词发音明显比句子差：

| 词 | 旧的单词音频 | 句子（新管线） |
|---|---|---|
| φωνή | `f`ɔːnˈɛː | **`p_h`**ɔːnˈɛː |
| θυμιάω | `θ`ˌymiˈaɔː | **`t_h`**ˌymiˈaɔː |
| χείρ | `x`ˈeːr | **`k_h`**ˈeːr |

三处缺失：① 送气塞音没还原（28.2% 的词受影响）② 完全没有音高重音
③ ᾱ/ῑ/ῡ 长音没补。另外编码只有 ~29 kbps（句子是未压缩 WAV）。

**现在单词改用 `tools/gen_word_audio_prosody.ts` 生成，它直接 import
`app/src/lib/prosody.ts` 与 `psola.ts`——与句子是同一份代码**，不会再各自演化：

```bash
# 打包（脚本 import 了 .ts，必须先 bundle）
cd 逻各斯 && app/node_modules/.pnpm/node_modules/.bin/esbuild \
  tools/gen_word_audio_prosody.ts --bundle --platform=node --format=esm \
  --outfile=/tmp/genwords.mjs \
  --external:../app/public/espeak/espeak-ng.js
node /tmp/genwords.mjs --limit=20     # 试跑
node /tmp/genwords.mjs                # 全量（约 15,710 个，30 分钟）
```

编码码率同时从 29 kbps 提到 **48 kbps**（实测落点 36–44 kbps）。

### 还原古音：送气塞音与 [zd]

eSpeak 的希腊语音素表**继承自现代希腊语**（`espeak-ng-data/lang/grk/grc` 只有 4 行，
音素表委托给 `el`），所以有几处系统性偏离阿提卡重建：

| 字母 | eSpeak 实际 | 阿提卡重建 | 影响面 |
|---|---|---|---|
| φ θ χ | `f θ x`（擦音） | **`pʰ tʰ kʰ`**（送气塞音） | **28.2% 的词** |
| ζ | `z` | **`zd`** | — |

**修法：纯文本替换，不必重编译 WASM。** `dictsource/grc_rules` 里的字母→音素映射是固定的，
只要把字母换成「能触发正确音素」的写法即可：

```
φ → πɦ      π→p、ɦ→h，相邻即得「塞音+送气」= [pʰ]
θ → τɦ      → t_h_   [tʰ]
χ → κɦ      → k_h_   [kʰ]
ζ → ζδ      → z_d_   [zd]
```

`ɦ`（U+0266）是 eSpeak 内部表示粗气号的字符，规则里有 `ɦ → h`。
实测**重音位置不受影响**（`Θουκυδίδης` 仍是 `t_h_ˌuː_k_y_d_ˈi_d_ɛː_s_`）。

代码：`restoreAncientPhonetics()`（`src/lib/prosody.ts`）。
开关：「我的 → 例句朗读 → 还原古音」。

### ᾱ/ῑ/ῡ 长音补偿

eSpeak 只在 η→ɛː / ω→ɔː 上标长音，**带 circumflex 的 ᾱ/ῑ/ῡ 完全没加长**
（实测 μῦθος 的 ῡ = 72ms，与 λύω 的 ῠ = 71ms 几乎相同）。

修法：在韵律设计里为这些音素生成**时长映射锚点**，交给 TD-PSOLA 的 `durAnchors` 拉伸。
倍数 **1.55** 取自 eSpeak 自己对 ω:ο 的时长比（136ms/86ms）——
即「用它自己的长音比例，补它漏掉的那部分」。

### 朗读粒度与性能

原来朗读按钮把**整段**交给 eSpeak，于是一段里多个句子之间的停顿听起来像
「莫名的停顿」，用户也没法一句一句听，而且合成慢。

现在按句切分（`splitSentences()`，古希腊语句末标点 `.` `;`（问号）`·` `!`），
并提供三种模式：

| 模式 | 行为 | 每次合成的音频 |
|---|---|---|
| **逐句**（默认） | 点一次读一句，再点读下一句 | **~1.3s** |
| 连播 | 从当前句起自动一句接一句 | 逐句合成、顺序播放 |
| 整段 | 一次读完整段 | ~20s |

**实测延迟**：逐句模式点下去 **522ms** 出声（整段模式要合成 20s 的音频）。

性能优化（28.6s 音频的段落，韵律处理总耗时 **1.8s → 0.34s**）：

| 阶段 | 优化前 | 优化后 |
|---|---|---|
| `pitchTrack` | 815 ms | **122 ms** |
| `pitchMarks` | 807 ms | **134 ms** |

两处改动：① `pitchMarks` 接受已有轨迹，不再重复估一次基频；
② 自相关的滞后搜索改为**粗搜（步长 3）+ 细搜（±3）**，精度不变。

> ⚠️ 走过一条弯路：曾为提速把自相关放到**降采样 4 倍**的信号上（快 16 倍），
> 结果基音标记定位失准——标记数量变多但位置全错，恒等重建从 1.0000 掉到 0.11。
> 基音标记必须在**全分辨率**下做。

### 音高重音：eSpeak 只标位置、不给调型

**这是最容易忽略、但对学习者最实质的一个缺陷。** 实测发现 eSpeak 的 `grc` 语音
**完全没有实现古希腊语的音高重音**：

```
φῶς（circumflex）→ f_ˈɔː_s_
φώς（acute）     → f_ˈɔː_s_      ← 逐字符完全相同，整词 F0 差 0.1 Hz
```

15 组 acute/circumflex 最小对立体里 **14 组音素串一模一样**。也就是说它只标了
「重音落在哪个音节」，**没有给出任何调型**——而界面是标注重音符号的。

好消息：`ˈ` 的**位置**在 5,985 个词上与正字法 **100.0% 一致**，
所以不用自己算重音在哪，缺的只是调型。

**做法**（`src/lib/prosody.ts` + `src/lib/psola.ts`）：

```
文本 ──eSpeak WASM──► PCM + 每音素起止毫秒 + 词位置
                          │
     正字法(NFD) ──► acute / circumflex / 无重音 + mora 数
                          │
                 目标 F0 曲线（阿提卡调型）
                          │
            自研 TD-PSOLA（浏览器内，零依赖）
                          ▼
                    改造后 PCM
```

- **acute**：高调落在音节第二个 mora → 到音节末平滑升到峰
- **circumflex**：高调落在第一个 mora → 峰在音节约 45% 处后下降
- 正字法上无重音的附着词（ἐν / εἰς / οὐ / τις…）：不带调
- 形状用**平滑函数**而非折线：折线的尖角会让基音周期增量突变，实测 HNR 会掉 6–8 dB

**为什么用 PSOLA**：它在**基音周期**尺度上搬运波形，每个周期内部的波形
（= 共振峰 = 元音音值）原样保留，所以**只改基频与时长，不动阿提卡音值**。

**验收指标**（`app/scripts/prosody-test.mjs`，6 项；用 WebAudio 解码后自相关测 F0，
不依赖试听）：

| 对立体 | eSpeak 原始差 | 改造后 |
|---|---|---|
| πώς / πῶς | 3 Hz | **17 Hz** |
| τίς / τις | 2 Hz | **18 Hz** |

恒等重建（走完整 PSOLA 但不改调型）与原始的相关性达 **1.0000**，
确认 PSOLA 本身不引入明显损失。代价是 HNR 降 2–4 dB。

**幅度可调**：「我的 → 例句朗读 → 重音幅度」。幅度越大 PSOLA 要搬动的周期越多、
相邻窗相位越容易错开，HNR 随之下降——所以默认取保守值（≈ +6.4 半音），用耳朵定。

试听对比：`研究/ts-prosody/试听对比.html`（三列：原始 / 恒等 / 改造后，
**先比 ①② 再比 ②③**，避免把「重新合成的固有损失」误当成改进）。

### AI 翻译：古典文本的中文怎么办

古典文本（荷马、柏拉图、修昔底德……）的中文译文**在版权期内**，没有可自由分发的来源，
所以内置译文只能陆续人工补齐。缺的部分可以在阅读页**用你自己的 API Key 现场翻译**
（「我的 → AI 翻译」里配置）。

**为什么必须是「自带 Key」**：这是个纯静态站，没有后端。而古希腊语→中文的
**机器翻译模型不存在**——HuggingFace 上 20 个 "ancient greek" 模型全是 BERT 编码器；
`opus-mt-grc-*`、NLLB 的 `grc_Grek` 都没有（详见 `tools/mt_experiment.py` 的实验记录）。
大语言模型是唯一可行的方案，自带 Key 则是唯一既不产生服务器成本、
又不把 Key 写进公开代码的做法。

**支持哪些服务商**——静态站在浏览器里直接调 API，**服务商必须允许跨源请求（CORS）**。
实测（带 `Origin: https://hsmulingsheng.github.io`）：

| 服务商 | CORS | 能否直连 |
|---|---|---|
| DeepSeek | 回显本站源 | ✅ 默认 |
| 智谱 GLM | 允许 | ✅ |
| 阿里通义 | `*` | ✅ |
| OpenAI | 无 CORS 头 | ❌ 需自建代理 |
| Anthropic | 403 | ❌ 需自建代理 |

**实现要点**
- `src/lib/aiTranslate.ts`：服务商注册表、提示词、JSON 解析、本机缓存
- 提示词要求输出 `{"zh": [...]}`（`json_object` 模式要求顶层是对象）；
  服务商不支持该参数时自动去掉重试一次
- 每批 ≤8 段：段落多时模型容易漏条或截断
- 译文缓存在本机 IndexedDB（键含原文哈希 + 模型名），重复阅读不再花额度
- 错误提示都带补救建议（Key 无效 / 限流 / 返回不是 JSON），不丢已翻好的部分
- **CSP 调整**：`connect-src` 由 `'self'` 放宽为 `'self' https:`。
  这是必然代价——用户指定的端点无法写进静态白名单。
  脚本仍受 `script-src 'self'` 约束、表单被 `form-action 'none'` 锁死。

验收：`app/scripts/ai-translate-test.mjs`（**19 项**，含 4 条错误路径）。
测试用 route 拦截模拟服务商，但**请求本身是真的**，所以能验证 URL、鉴权头、
提示词内容、JSON 解析、渲染、缓存——当初正是这个测试抓到 CSP 把请求全拦了。

### 国际音标（IPA）

每个词都注有国际音标，**古典阿提卡（Attic）重建**，用 CLTK 的
`cltk.phonology.grc.transcription.Transcriber("Attic", "Probert")` 生成——
重建方案出自 **Probert (2010)**, *A Companion to the Ancient Greek Language*。

```
λόγος      [ló.gos]          Ζεύς       [zdéws]        ← ζ = [zd]
ἄνθρωπος   [ɑ́n.tʰrɔː.pos]    πρᾶγμα     [prɑ̂ŋ.mɑ]      ← γ 在 μ 前 → [ŋ]
ἡμέρα      [hɛː.mé.rɑ]       ψυχή       [psy.kʰɛ́ː]     ← υ = [y]、χ = [kʰ]
```

几个特征：气号 → h（`ὁ [ho]`）、高调用声调符号标在元音上、音节用 `.` 分隔、
连读音变（r 清化 / s 浊化 / 鼻音同化）已处理。

- 生成：`HOME=$PWD/.cltk-home tools/venvs/grc-ipa/bin/python tools/build_ipa.py`
  → `data/ipa.json`（**100% 覆盖**，15,686 词）
  （CLTK 会在 `$HOME` 下建数据目录，所以必须重定向 HOME）
- 字段：`lesson-*.json` 的 `ipa`、`index.json` 第 6 项
- `build_app_data.py` 只**读取** `ipa.json`，所以重建数据不需要装 CLTK
- 展示：词条详情、词典列表、学习卡（**拼写步骤除外**——那题就是考拼写，
  给音标等于给答案）
- 字体：Gentium Plus（SIL，为语言学研究设计）已内置，IPA 覆盖完整
- 验收：`app/scripts/ipa-test.mjs`（17 项，含 10 项音值特征断言，
  防止换实现后音值悄悄退化）

> 词条里有些是「介词 + 格标注」的写法（`ἐπί [+acc]`），方括号是语法说明不是词的一部分，
> `build_ipa.py` 会先剥掉再转写。

### 希腊语输入：拉丁键盘直接转写

**默认方案是 iOS「希腊语」键盘的键位映射**——QWERTY 的物理位置不变，
只把该位置输出的字符换成希腊字母。所以 `u` 是 θ、`w` 是词尾 ς、`v` 是 ω、
`c` 是 ψ、`j` 是 ξ，这几个最容易记混：

| 键位 | 输出 | 键位 | 输出 | 键位 | 输出 |
|---|---|---|---|---|---|
| q | ; | a | α | z | ζ |
| w | ς | s | σ | x | χ |
| e | ε | d | δ | c | ψ |
| r | ρ | f | φ | v | ω |
| t | τ | g | γ | b | β |
| y | υ | h | η | n | ν |
| u | θ | j | ξ | m | μ |
| i | ι | k | κ | | |
| o | ο | l | λ | | |
| p | π | | | | |

- **Shift** 输出大写（`Shift+a`→Α）
- **分号 `;` 是重音死键**：先按 `;` 再按元音 → `;a`→ά、`;v`→ώ；`Shift+;`（即 `:`）是分音符 → `:i`→ϊ
- **数字 1-6/0 加多调符号**：`1`重音 `2`抑音 `3`扬抑符 `4`粗气号 `5`柔气号 `6`下加字母 `0`分音符。
  iOS 的单调键盘**打不出气号**，而古希腊语离不开气号，所以这一半由数字补上。
  可叠加：`a41`→ἅ
- **词尾 σ 自动写成 ς**（希腊语词尾不可能是 σ），所以 `logos` 能自然打出 λογος

另外保留三种方案，在「我的 → 设置」里可切换：

| 方案 | 说明 |
|---|---|
| **iOS 希腊语键盘**（默认） | 上面这套键位映射 |
| **按读音音译** | `a→α · ē→η · ō→ω · ch/ph/th/ps→χ/φ/θ/ψ · h 起头为粗气号`；`anthropos`→ἀνθροπος |
| Beta Code | `h→η · w→ω · q→θ · f→φ · c→ξ · y→ψ`；大写前加 `*` |
| 现代罗马化 | `v→β · th→θ · ch→χ`，不区分长短与气号 |

> `ios` 这个 id 早先指「按读音音译」，现指 iOS 键盘。这样互换之后，
> 老用户存着 `ios` 会**自动落到新的键盘方案**上，不需要额外的迁移逻辑。

规则实现见 `app/src/lib/greekInput.ts`；验收见 `app/scripts/translit-test.ts`
（**219 项断言**：143 项拿 macOS 的 `kCFStringTransformLatinGreek` 当基准验证音译方案，
50 项逐键验证 iOS 键盘的键位对应，其余覆盖死键、数字符号、词尾 sigma 等）。

### 例句发音

**所有例句都能读**——词条详情里的新约与古典语料例句、语法闯关里的教材例句、
读新约的每一节，句尾都有喇叭按钮。

实现方式不是在构建期预生成音频，而是**把 eSpeak-NG 编译成 WebAssembly 放进浏览器实时合成**：

- 应用里去重后有 **1.8 万条例句、合计约 81 小时**，预生成要 380–760 MB，网页版扛不住
- 实时合成只需一次性加载 24 MB 引擎（之后走缓存），**任意文本都能读、零存储**
- 首次点击要等引擎下载（本地约 0.5 秒）；之后同一句走内存缓存，约 200 毫秒响应

**语料清理**：朗读效果差的一大半来自文本本身。语料里有几类噪声已被清理：

| 噪声 | 数量 | 处理 |
|---|---|---|
| HTML 实体没反转义（``&quot;``） | 1,274 条古典例句 | 反转义 |
| SBLGNT 校勘符号 ``⸀⸁⸂⸃`` | 6,617 处 | 剥离 |
| 尾部编辑标记 ``E`` | 3,250 条古典例句 | 剥离 |
| 字模损坏（``G3ωοῦμεδ``） | 数十条 | 整条丢弃 |

清理规则见 [`tools/textclean.py`](tools/textclean.py)，**按 Unicode 码位判定希腊字母**——
希腊大写 Α Β Ε Ζ Η Κ Μ Ν Ο Ρ Τ Υ Χ 与拉丁同形，不能用 ``[A-Za-z]`` 一刀切。
`assert_greek_caps_intact()` 做回归校验：清理不得弄丢任何希腊大写（当前 16,329 个一个不少）。

### 例句朗读：两种引擎

「我的 → 设置 → 练习模式 → 例句朗读引擎」可以切换：

| 引擎 | 体积 | 首句延迟 | 音质 |
|---|---|---|---|
| **高清**（默认） | 一次性下载 **128MB**（模型 114MB + 运行时 14MB），之后离线可用 | 约 0.7 秒（首次加载 1 秒） | **Meta MMS-TTS 神经语音**，接近真人 |
| **轻量** | 无需下载（内置 24MB 引擎） | 约 0.2 秒 | eSpeak 共振峰合成，音色机械 |

**客观差别**（同一句话）：

| | 采样率 | 平均振幅 | 近似静音占比 |
|---|---|---|---|
| 轻量 eSpeak | 22.05 kHz | 0.042 | ~40% |
| **高清 神经语音** | 16 kHz | **0.125** | 极低 |

平均振幅高 3 倍意味着**语音是连续密实的**，而不是一顿一顿——这正是"机械感"的来源。

神经模型来自 `facebook/mms-tts-grc`，经 ONNX 导出 + 在浏览器内用 onnxruntime-web 推理
（不预生成音频：1.8 万条例句合计 81 小时，预生成要 380–760MB）。

**语速与等待时间**：模型本身的语速调不了（VITS 的时长由权重决定，
config 里的 `speaking_rate` 改了无效，实测只是随机时长预测器的噪声），
所以语速用 `<audio>` 的 `playbackRate` + `preservesPitch` 做**保音高变速**，
可在「设置 → 高清语音语速」里调（55%–125%，默认 82%，模型原速约 190 词/分偏快）。

首声延迟做过三轮优化（冷点击 **7.5 秒 → 2.5 秒**，悬停后 **118 毫秒**）：

| 问题 | 处理 |
|---|---|
| 悬停预生成与点击**并发跑两次推理**，抢同一条 WASM 单线程（3.5s 拖成 7.5s） | 同一句的并发请求合并为一次 |
| 悬停预生成的是**整句**，点击后是**分段**，两者无法复用，白跑一遍 | 预生成改用与播放相同的切分 |
| 整句一次性推理要 2–4 秒才开始出声 | **分段朗读**：按标点切开，首段好了就出声，其余边播边合成 |
| 每次刷新页面都要重新推理 | 合成结果写入 Cache Storage，**跨会话秒出**（~160ms） |
| 会话创建 + 首次推理要 1.8 秒 | 启动后 `requestIdleCallback` 里**提前预热**（含一次空推理吃掉 JIT 开销） |

**硬件加速试过了，不行**：`navigator.gpu` 在目标浏览器上可用，但 ORT 的 WebGPU
后端没有实现这个模型需要的 `GatherND` 算子（`/duration_predictor/flows`），
建会话直接失败；多线程推理也实测无收益（10 核机器 2643ms vs 2615ms），
所以最终仍是单线程 WASM。

> ⚠️ **该模型是 CC-BY-NC 4.0（非商用）**，详见 [`NOTICE.md`](NOTICE.md)。
> 商用请切回「轻量」，或删除 `app/public/mms-grc/`。

**轻量引擎的调优**：eSpeak 默认 rate=120 有效语速只有 13 字符/秒（自然希腊语约 20–25），
已改为 168（→19.4 字符/秒）；音色有 6 种变体可选。

**现成录音的调研结论**：逐节录音确实存在（如 CC BY 4.0 的
[MP3_SBLGNT_fast](https://github.com/eliranwong/MP3_SBLGNT_fast)），但它 README 明确写了
**本身就是 TTS 生成的**，且只覆盖新约、还得再下载几百 MB——与其如此不如自己合成，
还能顺带覆盖古典语料与 Smyth 教材例句（这两部分根本没有录音）。

> ⚠️ **授权变化**：eSpeak-NG 是 **GPL-3.0**，随应用打包会把**整体**置于 GPL-3.0，
> 详见 [`NOTICE.md`](NOTICE.md) 与 [`LICENSE`](LICENSE)。
> 不想采用 GPL，把 `app/src/lib/flags.ts` 的 `USE_TTS` 改成 `false` 重建即可——

### 教材层：Smyth《A Greek Grammar for Colleges》(1920)

教材是英语世界最权威的古希腊语参考语法，1920 年出版，**已进入公有领域**。
我们从它整理出：

- **3,048 个编号小节**（按 Part / Chapter / Section 三层定位），课程单元与 § 号一一对应，可随时查阅
- **1,202 条教材例句**——Smyth 正文引用的**真实古典希腊语**（色诺芬、柏拉图、修昔底德、欧里庇得斯…），
  全部带出处（如 `X. A. 4.1.13`）与英文译文；每条都自动挑出一个**可做形态分析的目标词**，
  并按形态归属到对应课程单元

希腊语原文在 TEI 里是 Beta Code（`e)/fh` = ἔφη），
转换用 MIT 许可的 [beta-code](https://github.com/perseids-tools/beta-code-py)，并对词尾 σ→ς 做了补齐。

**数据驱动的部分**：`词尾速查` 与 `变格/变位范例` 都是从新约语料里
**实际出现过的词形**聚合出来的（例如「属格·单数·阳性」中 -ου 占 89%、「主格·单数·阳性」中 -ος 占 76%），
所以看到的就是真实分布。


**词库**：全文检索（希腊语可忽略重音，也可按中文释义搜）、收藏、难词（遗忘 ≥4 次）、待复习、未学筛选；
词条详情含释义、构词、例句、语料中的全部屈折形式、Logeion / BibleHub 外链。

**中英释义并存**：每张卡同时列出「中文释义」与「英文释义」，中文为主、英文保留原牌组措辞。

**读新约**：7,927 节 SBLGNT 原文 + 和合本对照，点任一希腊语词即可查义
（55 万条 form→lemma 反查表把屈折形式还原到词典形）。

**统计**：连续打卡、28 天活动、记忆保持率、平均记忆强度、记忆强度分布、各词书进度。

**打包注意（本机特有）**：工作区在 iCloud/FileProvider 管辖下，系统会持续给文件打上
`com.apple.provenance` / `FinderInfo`，导致 `codesign` 报
「resource fork, Finder information, or similar detritus」而签不上名——**未签名的 app 在 Apple Silicon 上会被内核直接 SIGKILL**。
所以 `desktop/bundle.mjs` 的做法是：**先在 `/tmp` 里组装并签名，再搬回工作区**（已验证搬回后签名仍有效）。
另外 `codesign -dv` 的诊断信息走 stderr，判断签名结果时必须合并两个流。

**零注册分享**：`cd app && node scripts/share.mjs` —— 起服务 + 开临时公网隧道，
打印一个 `https://xxxx.trycloudflare.com` 网址和二维码。**你和用的人都不用注册**；
因为是 HTTPS，手机还能装成 PWA 离线用。缺点是电脑得开着、关掉窗口就失效。

**公开发布（永久网址）**：`cd app && node scripts/make-deploy.mjs` 会生成 `deploy/` 与 `logos-site.zip`
（**音频全部换成自生成版本**，不含来源不明的原牌组录音），
再按 [`DEPLOY.md`](DEPLOY.md) 传到 Cloudflare Pages / Netlify / GitHub Pages 即可。
部署到 HTTPS 之后，手机端才能真正装成 PWA 并离线使用。

**多设备使用**：`启动逻各斯.command` 默认监听所有网卡，终端会打印局域网地址和一个二维码——
手机、平板连同一个 Wi-Fi 就能扫码打开，界面是自适应移动端的。
学习进度存在**各自设备的浏览器**里（不落服务器），想同步就用「我的 → 导出/导入备份」。
只想本机用就加 `--local` 参数（`node scripts/serve.mjs 4178 --local`）。

**数据与离线**：进度存本机 IndexedDB，支持 JSON 导出 / 导入；
PWA 支持安装到桌面/手机并**完全离线使用**（安装期预缓存 9.9 MB，一键缓存全部约 157 MB，含全部音频）。

## 已知限制

- **1,067 个词条没有例句**（GLAUx 未收录的极罕见词 / 通行本异形）。
- **音频覆盖 100%**：4,136 条沿用原牌组录音，其余 11,523 条用 eSpeak-NG 的 `grc` 语音生成。
自动发音用「排定→必须真正播放」的不变式做了回归测试（`scripts/smoke.mjs`），
可以捕获「单词出现却不出声」这类问题。
  两者音色不同（原录音更自然、eSpeak 音质偏机械但**读音是重构的古希腊语音系**，教学上更正确）。
  想全部统一成一种音色，可跑 `node scripts/build-tts-audio.mjs --all` 覆盖生成。
- **古典例句的中文翻译由本项目流水线生成**，质量不及专业译本，长句与诗歌尤其可能有偏差。
- **少量古典例句可能不是该词本身**：GLAUx 的词形还原对 AGDT 金标准的实测准确率是 86.5%，
  所以偶尔会把近形词（如 ἰάζω / ἰάομαι、κριτός / κρίτος）认成目标词。句子本身仍是真实希腊语、
  译文也如实翻译，只是高亮的词可能与词条不符。
- **词形变化表来自新约语料**，古典词条多数没有屈折形式数据。
- 现有 mp3 的再分发许可不明（原牌组来源），**本 App 仅供个人本地使用**。
- 桌面版为**本机 ad-hoc 签名**，未做公证，不能直接分发给别人。
- **手机上的网页版不能离线使用**：Service Worker 只在安全上下文（HTTPS 或 localhost）生效，
  用 `http://192.168.x.x` 打开时装不上离线缓存。要离线请用桌面版，或自备 HTTPS。
- 局域网访问要求手机和电脑在**同一个 Wi-Fi**；离开这个网络就打不开了
  （不提供公网穿透——那需要额外的隧道服务，且有安全代价）。
